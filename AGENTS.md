# Правила Filmoteka

- **KB-First.** Начни с [указателя](KB/README.md) и [состояния](KB/CURRENT_STATE.md). Читай разделы по задаче, ищи через rg. Пропускай зависимости, сборки и полные успешные логи.
- Владелец утверждает продукт, дизайн, расходы и существенные архитектурные изменения. До утверждения архитектуры работай только над проектированием. Правила самостоятельных решений и эскалации — в инженерном регламенте.
- Агент-разработчик (Sol) реализует этапы, локально тестирует, исправляет ошибки, создаёт локальные коммиты и передаёт их отдельному агенту-ревьюеру через КБ. Push, создание PR и merge закреплены за ревьюером.
- Агент-ревьюер в отдельном чате Codex независимо проверяет код, контракты и результаты тестов, возвращает существенные замечания разработчику, проверяет секреты и приватные данные перед публикацией, публикует рабочие ветки и создаёт PR в `FerMaxim/filmoteka`. Ревьюер проверяет GitHub Actions и выполняет merge только с полномочиями владельца и по инженерному регламенту.
- Агент эксплуатации в третьем чате настраивает и обслуживает сервер, деплоит проверенный SHA main и проверяет результат по [OPERATIONS](KB/OPERATIONS.md). Код приложения передаёт разработчику, версионируемые серверные изменения — ревьюеру. Права на push и merge к нему не переходят.
- Передавай задачи по [WORKFLOW](KB/WORKFLOW.md) через карточки `KB/TASKS/T-NNN.md`; обновляй CURRENT_STATE при передаче, возврате, интеграции и изменении состояния сервера.
- Для поведения сверяй [требования](KB/PRODUCT.md), для технических границ — [архитектуру](KB/ARCHITECTURE.md) и [решения](KB/DECISIONS.md). Сохраняй SOURCE_MATERIALS без изменений.
- При проектировании, изменении и ревью UI обязателен Anthropic `$frontend-design`. Используй [проектную копию](.agents/skills/frontend-design/SKILL.md), в том числе при совпадении имён в списке. Приоритет у [согласованного дизайна](KB/DESIGN.md). Значимые экраны проверь в браузере и приложи скриншоты.
- Docker и Compose не используются в разработке, GitHub Actions и на сервере. Django и PostgreSQL запускаются нативными процессами. Сервер готовит агент эксплуатации в отдельной задаче; фактическая выкладка требует определённой среды и полномочий владельца.
- Следуй [инженерному регламенту](KB/ENGINEERING.md) по Git, разрешениям на merge, проверкам, безопасности и изоляции БД. Сохраняй чужие изменения. Не публикуй без полномочий.
- **Write-Back.** Обнови затронутый контракт и журнал значимых решений. При передаче запиши статус, выполненные проверки и следующий шаг. План не считать реализацией, невыполненные проверки не отмечать успешными.
