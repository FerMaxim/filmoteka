# T-006 · Серверная конфигурация на независимое ревью

Эти файлы подготовлены и проверены эксплуатацией на Ubuntu 22.04 LXC с 1 CPU/1 ГБ RAM. Они не являются релизом приложения и не разрешают выкладку текущей рабочей ветки. Факты и ограничения — в [T-006](../KB/TASKS/T-006.md), порядок передачи — в [OPERATIONS](../KB/OPERATIONS.md).

## Состав

- prepare-runtime.sh: первоначальная подготовка учётной записи/каталогов, PGDG, PostgreSQL 17 и Python/uv. Требует предварительной инвентаризации и установленных curl/ca-certificates/postgresql-common. Не универсальный unattended installer; применять после ревью на соответствующей ОС. На сервере первоначально установлен uv 0.13.10 и Python 3.13.18, затем эти версии закреплены в файле.
- prepare-database.py: однократное создание БД UTF-8 и ролей. Существующие роли/БД/конфигурацию сохраняет, завершаясь отказом. Секреты генерируются только на сервере и не выводятся. При частичном сбое требуется ручная проверка, автоматического удаления нет.
- postgresql-small.conf: устанавливается в /etc/postgresql/17/main/conf.d/filmoteka.conf. Изменения startup-параметров требуют перезапуска PostgreSQL; в T-006 выполнены до установки приложения и загрузки данных.
- filmoteka.service и filmoteka-start: systemd и Gunicorn, 1 worker/2 threads, loopback:8000, процесс без login/sudo, лимит 384M. Выпуск root-owned; запись разрешена только в media. .release-approved — эксплуатационный предохранитель; ставится root только после проверки передачи ревьюера, не доказывает приёмку сам по себе.
- nginx-loopback.conf: локальная точка контроля 127.0.0.1:8080. nginx-ip-tls.conf: HTTPS по IP, адрес подставляется на сервере, ключ TLS хранится только там. Для неизвестного Host запрос закрывается. Прямые пользовательские media пока не выдаются: политика загрузок не реализована. Лимит ingress 5M технический, не продуктовое ограничение фото.
- filmoteka-health.service/timer и filmoteka-health: локальная проверка двух health URL и свободного диска каждую минуту после появления принятого выпуска. Без выпуска служба пропускается; это не успешная проверка сайта. Внешних уведомлений нет.
- requirements-wsgi.txt: production WSGI-зависимость для согласования ревьюером. Gunicorn 27.0.1 проверен в отдельном probe-venv. В зависимостях приложения его пока нет; перед релизом согласовать закреплённую установку в release venv либо передать добавление в uv.lock разработчику. Не менять приложение на сервере.
- verify-infrastructure.py: проверка SCRAM/identity/UTF-8/запрета DDL и временный WSGI probe. Требует подготовленного /opt/filmoteka/probe-venv с Gunicorn. Probe не использует приложение, отвечает только на /__ops_probe, останавливается в finally; настоящий readiness этим не проверяется. Перед запуском убедиться, что 8000 свободен. Каждый probe использует эксклюзивный временный каталог и собственное имя unit; очищает только успешно запущенную им службу. При отказе stop файлы сохраняются. На живом сайте не запускать.

## Выпуск после передачи ревьюера

Получить принятый полный SHA main, CI/full, ограничения, миграции и разрешение целевой среды. Разместить только его в /srv/filmoteka/releases/SHA, установить из lock зависимости и согласованный WSGI, проверить настройки production. Секреты app.env: root:filmoteka 0640; migrate.env: root:root 0600. DDL выполнять отдельно ролью миграций, не службой сайта. Значения окружения не печатать и не передавать через аргументы команд.

Статика публикуется в /srv/filmoteka/shared/static, media в /srv/filmoteka/shared/media. STATIC_ROOT текущего приложения находится внутри выпуска: порядок collectstatic и переключения каталога static необходимо сверить с конкретным SHA. Код и .venv после подготовки — root-owned, доступны группе filmoteka только для чтения/выполнения. /srv/filmoteka и shared допускают traversal, каталоги releases/media и конфигурации ограничены. nginx не добавлен в группу с доступом к секретам.

До переключения проверить совместимость миграций с предыдущей версией. Установить root-owned маркер и переключить current на конкретный выпуск; запустить systemd. Проверить реальные /health/live, /health/ready, HTTPS, static, пользовательские сценарии и журналы; не путать с инфраструктурным probe. Фактическую проверку перезагрузки выполнять только в согласованное окно.

## HTTPS и сеть

Домен не предусмотрен владельцем. Частный IP и схема маршрутизации не публикуются в Git. Включён только TCP 443 дополнительно к прежнему SSH; 5432 и 8080 слушают loopback, 8000 используется только WSGI. Настройки Proxmox, роутера, NAT и внешнего DNS не изменялись; доступ проверен с компьютера эксплуатации, доступ произвольного посетителя из интернета не доказан.

Самоподписанный сертификат выдан на год, до 25 ноября 2027 17:11 UTC. Проверена TLSv1.3 с проверкой сертификата, без insecure-режима. Пользователям требуется доверие к публичному сертификату на клиенте; доверие автоматически не устанавливалось. Закрытый ключ root:root 0600 в /etc/filmoteka/tls/server.key. До истечения сертификата выпустить новый через защищённый доступ, проверить SAN/срок/fingerprint, nginx -t и reload; передать новый публичный сертификат клиентам. Автоматическое обновление доверия клиентов не настроено. Переход на домен/ACME — отдельная будущая настройка.

## Журналы и обслуживание

nginx access log отключён для Filmoteka; error log — warn, штатная ротация daily/14 сжатых файлов. PostgreSQL не пишет SQL ошибки и значения параметров, штатная ротация weekly/10; службы используют systemd journal со штатными ограничениями и rate limit Filmoteka. Локальный health пишет только статус, не ответы и секреты. Получатель внешних уведомлений не назначен; внешний мониторинг не включён. Проверять systemctl --failed, свободный диск, срок TLS и журналы через защищённый доступ. Базовый образ старый: общий upgrade ОС и перезапуск существующих SSH/postfix не выполнялись; план обновления согласовать с владельцем/администратором Proxmox.

## Откат и данные

Владелец прямо исключил бэкапы/сохранения в этой среде (решение в DECISIONS и OPERATIONS). Автоматическое резервирование и проверка восстановления не выполняются. Установленный до уточнения restic не имеет репозитория, задания или копий. RPO/RTO восстановления данных не гарантируются: потеря контейнера может означать полную потерю БД/media. Это исключение не распространяется на остальные среды.

Для совместимой схемы: остановить только filmoteka, вернуть current и static на предыдущий принятый выпуск, запустить и повторить smoke. До первого выпуска предыдущей версии нет. При несовместимой схеме без копии восстановление невозможно: остановить выкладку до миграции, передать разработчику/владельцу план совместимого перехода. Не выполнять разрушительные миграции, не удалять данные и не обещать откат БД. Для возврата подготовки: остановить только новые службы Filmoteka, отключить их автозапуск, вернуть конфигурации nginx и правило 443 после проверки влияния; БД/media/секреты сохранять. Исходная nginx default-ссылка сохранена под /etc/nginx/sites-available/default.pre-filmoteka-link.
