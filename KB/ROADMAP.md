# Этапы и критерии завершения

| Этап | Проверяемый результат |
|---|---|
| 0. Проектирование | Пакет предложений готов к независимому ревью. Переход к фундаменту после утверждения владельцем |
| 1. Инженерный фундамент | Git main, шаблон PR и CHANGELOG, каркас утверждённого стека, lock, локальный запуск, безопасный .env.example и команды ENGINEERING. После R29 обязательна проверка нативного запуска из PowerShell и полного прогона в GitHub Actions без Docker. Миграции, smoke и изоляция PostgreSQL воспроизводятся, `quality-gate` подтверждает результат. См. [карточку нативного запуска](TASKS/T-001.md) |
| 1a. Визуальный прототип | Утверждённый Свет 04+ / Плотный перенесён в Django в рамках T-003. Профиль, каталог, пять вкладок и диалог оценки сравнены с эталоном в браузере; представлены парные снимки, анимации и отличия. Владелец принял реализацию до merge и масштабирования компонентов. См. [процесс и критерии](DESIGN.md#прототип-и-приёмка) |
| 2. Каталог и доступ владельца | На синтетических данных доступны вход, поиск, выбор целого произведения и приватная библиотека. Проверены чужая сессия, выход и повторная загрузка. Для реального каталога согласованы права и условия источника |
| 3. Библиотека и оценивание | Согласованы переходы, валидация и округление. U01–U05 воспроизводятся. Формула, нули, конкурентное сохранение, обновление тегов и откат покрыты проверками |
| 4. Рекомендации и обмен ссылкой | Утверждены доступ гостя и видимые поля. U06–U09 проходят в независимых сессиях. Приватные поля защищены сервером. Описание рекомендации отделено от комментария |
| 5. Готовность к эксплуатации | Агент эксплуатации готовит сервер и нативный деплой без Docker по [OPERATIONS](OPERATIONS.md), после определения среды и полномочий владельца. Ревьюер передаёт проверенный SHA main; агент эксплуатации подтверждает установленный SHA, запуск служб после перезагрузки и результат выкладки. Сценарии U01–U09 приняты. Образцы профиля и каталога сверены в браузере, снимки приложены. Успешны полный прогон, проверка production settings и HTTPS smoke. Настроены уведомления и внешние копии. Проверены восстановление на чистом окружении и возврат к предыдущей версии. CHANGELOG и тег соответствуют релизу. Запуск по разрешению владельца |
| 6. Сопровождение | Агент эксплуатации обслуживает сервер, проверяет доступность и копии, разбирает инциденты; ошибки приложения передаёт разработчику. По результатам эксплуатации обновляются зависимости, проверяются резервные копии, измеряются ошибки и задержки. Новая инфраструктура вводится при подтверждённой потребности или изменении требований доступности |

Проверки UI выполняются также в каждом затрагивающем его этапе. Отложенные функции перечислены в [продукте](PRODUCT.md).
