Без публичной регистрации, новых публичных полей, гостевого доступа, Kinopoisk, Redis/Celery, смены стека и настройки сервера. Серверное оценивание — следующий этап; формула, критерии, эмоции и рекомендации не меняются. UI по Свет 04+ / Плотный и проектному frontend-design, без нового оформления. ## Подготовка реализации после разделения T-005/T-006

CURRENT_STATE перечитан: T-005 остаётся у разработчика; карточка T-006 и OPERATIONS не редактируются. Подтверждения базового SHA в T-005 пока нет. Ниже подготовка по коду текущего checkout, не реализация и не снятие блокировки.

- Точки подключения: `filmoteka/base_settings.py` уже включает auth, sessions, AuthenticationMiddleware и CsrfViewMiddleware. Подключить accounts/catalog/collection, AUTH_USER_MODEL и стандартные context processors для request/auth. Accounts.User — AbstractUser с public_id UUID из ARCHITECTURE; публичных страниц/новых полей не вводить. Вход/выход стандартными Django views, logout только POST. Безопасный next проверяется Django.
- `filmoteka/urls.py` сейчас содержит health и две страницы прототипа. Новые серверные маршруты подключать отдельно: /accounts/login/, /accounts/logout/, /catalog/, /works/{id}/, /me/library/, POST /me/works/{id}/library/. Защищённые страницы требуют сессию; приватный queryset всегда фильтруется request.user. GET не пишет. Успех записи — 303, неверная форма — 422, недоступная работа — 404. Поля owner, чужие entry ID и произвольные флаги не принимаются.
- Добавление — явная команда added=True, остальные признаки не меняются. Entry с независимыми boolean по умолчанию False, version >= 1 и UNIQUE(owner, work); FK work с PROTECT. Операция atomic, создание через ограничение уникальности с повторным чтением; повторное добавление не меняет уже достигнутое состояние. Другие команды флагов и оценки не реализуются на этом этапе.
- Важный миграционный риск: текущий фундамент уже применяет стандартные auth-миграции, собственного User нет. До включения AUTH_USER_MODEL проверить историю на чистой одноразовой PostgreSQL и отдельно переход с прежней схемы с синтетическим пользователем/сессией. Не удалять и не пересоздавать dev-базу ради смены User. Если безопасный переход потребует выхода за утверждённые границы, вынести конкретное решение до исполнения; чистая установка сама по себе не доказывает корректность обновления.
- Синтетический каталог и тестовые аккаунты подготавливать явно и воспроизводимо, без автоматического создания аккаунтов при старте/GET и без production-паролей в миграциях. Новых пакетов не требуется.
- `tools/check.py` уже владеет одноразовым кластером и запуском Django; tests/conftest.py использует заранее мигрированную БД. Доработать tools/browser.py для реального серверного пути вместо одной проверки readiness; проверку штатного перезапуска выполнить на той же временной БД, а не новом кластере.
