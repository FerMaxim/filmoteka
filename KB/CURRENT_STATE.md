**Ограничения и следующий шаг.** Ревьюер повторно проверяет diff и публичность метаданных коммитов, включая адрес автора, публикует ветку после локального ревью и подтверждает `full`, артефакт, кэш, `quality-gate` и защиту `main` в Actions. Для проверки dev Compose в тестовой среде применить миграции, проверить readiness, сохранить контрольные данные, выполнить `docker compose down`, повторно поднять стек и подтвердить сохранность данных. На сервере после выкладки проверить запущенные сервисы, применённые миграции и HTTP readiness. Для рабочей поставки роль web и роль миграций требуется разделить в конфигурации среды. В базовом Compose web использует роль, создаваемую `POSTGRES_USER`.
