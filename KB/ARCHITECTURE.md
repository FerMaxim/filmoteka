# Архитектура Filmoteka

R25 и R29/R31. Один модульный монолит на Python 3.13, Django 5.2 LTS, psycopg 3 и PostgreSQL 17. Серверные шаблоны, CSS и ES-модули. PostgreSQL обеспечивает NUMERIC, ограничения и блокировки строк. Сессии в БД позволяют отдельно масштабировать web. Новый компонент, поисковик, очередь или сервис требует измеренного ограничения. Границы и стоимость проверять до смены стека.

## Модули и инварианты

| Модуль | Ответственность |
|---|---|
| `filmoteka/` и HTTP-слой | Настройки, URL, WSGI, форма и оркестрация модульной операции |
| `accounts/` | Пользователь, сессии и политика видимости профиля |
| `catalog/` | Общая Work, локальный поиск, границы интеграции по [CATALOG](CATALOG.md) |
| `collection/` | Личная Entry, признаки и будущие оценки, эмоции, рекомендации |
| Шаблоны, CSS и ES-модули | Представление готовых данных и интерактивность |

Accounts и catalog самостоятельны. Collection использует их модели и штатные операции. HTTP получает владельца из сессии, прикладывает политику доступа до рендера. GET не меняет доменные данные. Ограничения и формула имеют по одной серверной точке. Приватные поля фильтруются до передачи шаблонам. Межмодульные сценарии проверяются через HTTP.

## Реализовано в main · этапы 1–2а

- `accounts.User` наследует AbstractUser. AdoptUser атомарно создаёт таблицу или принимает прежнюю `auth_user`, сохраняя имена таблиц, PK, пароли, связи, права и сессии. Расширяет PK до bigint, назначает уникальный UUID public_id и переносит content type с permission ID. Обратная миграция запрещена. Возврат требует проверенного плана сохранения данных.
- Work хранит непустые title и kind без owner. Совпадение названия не означает тождество. Entry имеет UNIQUE(owner, work), независимые `added`, `watched`, `want_to_watch`, `favorite` с False по умолчанию и `version ≥ 1`. Дочерние данные удаляются каскадом с владельцем или Entry, используемая Work защищена. Физическое удаление пользовательских данных требует согласованного сценария.
- `GET /catalog/` ищет синтетические Work по q до 300 символов, 24 результата на страницу. `GET /works/{id}/` и `GET /me/library/` защищены сессией, библиотека ограничена владельцем. `POST /me/works/{id}/library/` принимает только `added=true` и CSRF. Повтор не создаёт дубль и не меняет версию. Создание и смена флага атомарны с блокировкой.
- Вход и выход через `/accounts/login/` и `/accounts/logout/` используют Django auth, ротацию и POST/CSRF для выхода. Защищённые HTML-страницы направляют гостя ко входу. Успех обычной формы → 303, ошибка → 422, недоступный объект → 404.
- `/health/live` проверяет процесс, `/health/ready` — готовность с БД. Ответы без внутренних подробностей. `/prototype/` демонстрационный, состояние оценок и фото хранится до перезагрузки. Доказательства этапа 2а — в [T-005](ARCHIVE/T-005.md).

## Запланировано

| Контракт | Граница |
|---|---|
| Интеграция 2б | Work и внешний ID по [CATALOG](CATALOG.md). Стадия T-008 в BACKLOG, технические детали в карточке. |
| Запись признаков и оценок | POST под `/me/works/{id}/`. Признаки передаются явными значениями, пропущенный флаг сохраняется. `rating/` принимает полную форму с версией; итог рассчитывается сервером по [PRODUCT](PRODUCT.md#оценивание). |
| Rating и эмоции | Rating с PK/FK entry_id, обязательным впечатлением, семью nullable NUMERIC с CHECK 0–10 и комментарием. Стабильный уникальный код Emotion, UNIQUE(rating_id, emotion_id), проверка допустимых тегов; используемая эмоция защищена. |
| Рекомендация | `recommendation/` и отдельная строка с PK/FK entry_id, описанием и created_at. Запись хранится отдельно от оценки. Допустимость рекомендации без оценки требует уточнения. |
| Профиль | Пагинированные GET `/p/{public_id}/rated/` и `/p/{public_id}/recommendations/` с проекцией полей по [R45](PRODUCT.md#профиль-по-ссылке--r45). Отдельный публичный JSON API вне текущего объёма. |

Числа считать через Decimal. Версию сверять под блокировкой Entry, при конфликте 409 с перечитыванием. При конкурентной вставке использовать UNIQUE и повторное чтение. Оценка, теги и версия меняются или откатываются вместе. Применять bigint PK, время UTC и штатные PK/UNIQUE/FK-индексы. Новый индекс обосновывать запросом и EXPLAIN.

## Фотография фона

Серверное хранение запланировано по R33. Проект — owner-only установка и сброс с CSRF, случайным именем и выдачей вне исполняемых каталогов. Проверять тип и содержимое, декодировать с лимитами байт и пикселей, перекодировать растр без метаданных. SVG и HTML исключены. Удалять прежний файл после успешной записи, сохраняя его при сбое. Лимиты, форматы, публичное чтение и зависимость декодера требуют решения перед реализацией. Демонстрационные 15 МБ не задают лимит.

## Рабочая серверная архитектура

Цель — небольшая аудитория и постоянные данные. Один web-узел с HTTPS-входом и закрытой PostgreSQL достаточен, возможен простой при его отказе. Измерять задержки, БД и ресурсы до масштабирования. Среда, копии, допуск и выпуск — в [OPERATIONS](OPERATIONS.md).
